# 业务代码任务分支规则

业务代码仓（包括嵌套仓）不得在 main、master 或默认远端分支直接修改或提交业务实现。根仓 feature 不代表嵌套业务仓已隔离。

1. 修改前逐仓检查当前分支、明确基线提交和未提交状态。
2. 默认分支上先创建并切换 `feature/<变更名>`；存在用户修改、并行或高冲突时用隔离 worktree，已有合适 worktree 可复用。
3. 只提交本任务相关文件，不覆盖、暂存或带入用户已有修改；无法安全分离时请求决定。
4. 发现本任务提交误落默认分支时停止后续提交，先创建任务分支保留提交；恢复默认分支或 reset 必须有明确授权，不自动恢复到远端。

仅读取或生成 patch 不要求切分支。推送、PR、删除未合并工作及其他外部/破坏性操作必须明确授权。
