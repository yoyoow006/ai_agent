# 优化工作流任务可观测性与模板护栏

## Why

`register-yuxiaor-projects` 的复盘表明，当前能看到单次门禁耗时，但无法把耗时稳定关联到具体任务、阶段和完整生命周期；同时，proposal 状态格式和归档索引格式依赖人工记忆，错误会在归档门禁才暴露。项目登记类变更也缺少可复用的生成入口，导致 registry、项目卡和路由索引需要手工同步。

## What Changes

1. 增加任务级 telemetry 约定和采集入口，记录任务名、阶段、开始/结束时间、耗时、结果和失败原因。
2. 修正 OpenSpec proposal 模板与生成校验，使 `模式:`、`状态:` 使用解析器要求的顶层格式。
3. 修正归档索引模板与校验示例，直接生成 `- \`变更名\` — ...` 的一对一索引行。
4. 优化 manifest 最终化流程，允许在归档前一次性写入最终 manifest 标识，减少反复 freeze/verify，并保留 stale 防护。
5. 提供项目登记生成/校验模板，覆盖 registry、项目卡和 `.ai/rules/index.md` 路由字段，降低手工遗漏。

## Impact

- 构建/验证：新增工作流工具与测试，不改变业务项目构建产物。
- 风险：指标与模板格式扩展需要兼容旧记录和既有变更。

## Scope

- 修改范围：OpenSpec 模板、工作流脚本/工具、相关测试和共享规范。
- 不修改：业务项目源码、现有项目登记事实、外部服务和 Git 推送行为。

## Acceptance

- 新建任务能产生可解析的 proposal 状态和正确归档索引格式。
- 任务级 telemetry 可按任务名和阶段汇总耗时，并保留失败记录。
- manifest 在最终化后仍能检测范围漂移，正常归档不需要无意义重复冻结。
- 项目登记模板或命令能生成并校验 registry、项目卡和路由索引的必填字段。
- 相关测试、快速门禁和归档门禁通过。

## Unverified scope

- 尚未确定现有 telemetry 文件是否需要兼容迁移，以及最终 manifest 是否作为独立审查记录保存。
- 尚未验证项目登记生成器应采用 Python CLI、模板脚本还是现有 OpenSpec 生成器扩展。

## Residual risk

- telemetry 结构变更可能影响现有本地指标读取者。
- 模板护栏收紧后，外部目标项目中的旧格式变更可能需要迁移。
