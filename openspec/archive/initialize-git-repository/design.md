# 设计

## 决策

当前 `.git` 是空目录且权限为只读；实施时需要先恢复其可写性，再运行 `git init`。Git 版本为 2.25.1，不依赖 `--initial-branch` 参数，初始化后用 `git symbolic-ref HEAD refs/heads/main` 在首次提交前固定 `main`。

根 `.gitignore` 采用仓库根锚定规则，避免子目录或安装资产中的同名路径被误忽略。双侧 SDD、`.ai-local`、`.worktrees` 和本地 Claude 设置属于本机状态，不进入初始提交。

OpenSpec 基线文件从随包共享资产复制，只添加当前根目录缺失的路径，不覆盖已有业务知识、memory 或活跃变更。这样工作流校验能获得与安装目标一致的 OpenSpec 结构，同时保留本仓库自定义内容。

## 替代方案

- 只运行 `git init`，不补 `.gitignore` 和 OpenSpec 基线：虽满足最小字面需求，但会把本地草稿和缓存纳入待跟踪清单，且工作流校验继续失败。
- 用安装器把共享层安装到当前目录：安装器面向单助手目标，而当前源仓同时包含 Codex 与 Claude 双侧适配，会引入入口冲突。
- 初始化后再另建分支提交初始状态：没有初始提交之前无法创建可用分支；本变更本身就是建立基线。

## 风险与边界

- 初始提交会收录当前未忽略的项目文件，包括已完成的 `fix-installer-python-38` 变更；这是用户要求初始化当前目录的自然结果。
- `.codex/sdd/` 中既有历史草稿会被忽略，不进入初始提交；如后续需要归档历史草稿，需另行明确授权。
- `.claude/sdd/.gitkeep` 位于被忽略目录内，仅保证当前本地校验的目录存在；初始提交不会跟踪该文件。
- OpenSpec CLI 未安装时默认校验允许显式 SKIP；本变更不联网安装依赖。
