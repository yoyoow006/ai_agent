# 设计

## 初步方向

本文件是严格模式 Open 四件套的一部分，不是独立实施计划。用户确认规范后，需要进入 Design 阶段产出 `openspec/plan/add-test-login-project.md` 并再次确认。

初步实现为独立的 Python 3.8 标准库包，核心服务保持可测试且不依赖 I/O。密码记录包含用户名、随机盐、PBKDF2 迭代参数和派生值；验证挑战记录随机码、过期时间和失败计数。会话 token 使用 `secrets.token_urlsafe`。

验证码投递采用可注入通道接口。单元测试注入内存通道读取验证码；命令行演示使用本地打印通道，仅作为测试项目体验，不模拟生产短信或邮件安全性。

## 关键边界

- 不修改安装器与工作流资产。
- 不登记 `.ai/kb/projects/registry.json`。
- 不承诺生产可用；真实系统还需要持久化、防滥用、安全投递、审计和账户恢复设计。
- 错误消息不区分未知用户和错误密码。
- 测试直接注入时间函数和投递通道，不睡眠等待真实时间。

## 待 Design 细化

- 模块与测试文件布局。
- 密码强度、盐长度、PBKDF2 迭代次数、验证码有效期和尝试上限的具体参数。
- API 异常类型与命令行演示输出。
- 红—绿测试清单、分支/worktree 落点与验证命令。
