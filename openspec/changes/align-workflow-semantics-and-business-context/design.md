# 设计：对齐工作流语义并补齐上下文路由

## 设计目标

在不削弱高风险正确性门禁的前提下，减少重复文档、重复确认、按 checklist 机械审查和 Verify/Archive 重复长测试；同时让已确认的流程语义在双运行时、用户文档和安装资产中保持一致，并为目标项目提供不含业务事实的业务词路由层。流程继续只有快速、标准、严格三种模式，OpenSpec 继续是唯一状态真源。

## 决策

### 1. 文档按决策复杂度生成

标准模式固定保留 proposal、delta spec、tasks；design 由可观察条件触发。tasks 承担可执行步骤，proposal 承担范围和影响，spec 承担行为契约。没有架构取舍时不再复制这些内容到 design。

### 2. 严格第二次确认按不可逆风险触发

第一次确认始终保留，用于锁定需求、边界与设计。Design 后只有出现不可逆或外部风险，或计划新增未确认选择时才再次等待用户；纯粹把已确认方案展开为命令和顺序时允许连续实施。权限、资金、Schema/迁移、数据删除和破坏性动作始终属于强制二次确认集合。

### 3. 审查单元由不变量定义

任务级审查的对象从 checklist 改为高风险不变量，例如“同一 revision 不重复建流”或“权限不得越租户”。一个不变量涉及多个文件和测试时只冻结一次范围、形成一次 finding 台账。Verify 的双关注面不变。

### 4. 验证区分语义变化与机械归档

新增 archive 入口或参数，组合 workflow core、OpenSpec required、归档索引、diff check 和 Git 状态检查。顶层 mutation/契约套件只在 Verify 或 Verify 后发生工作流语义变化时运行。Archive 通过 Git diff/manifest comparison 判断是否允许轻量路径，不能由人工口头声明跳过。

### 5. `.ai-local` 明确为缓存

最终审查 ID、comparison base、finding 结论、未验证范围和残余风险进入 OpenSpec 归档记录后，本地 manifest 目录不再承担追溯职责。清理必须以精确 change 路径为目标，不递归删除整个 `.ai-local`，也不处理活跃或不明目录。

### 6. 流程语义以根入口和主规格为 canonical，安装资产必须同步

Codex 与 Claude 根入口、README/介绍文档、共享 overview、阶段技能和安装资产不得各自保存第二套流程算法。本次把“标准三件套+条件 design、严格硬风险触发二次确认、高风险不变量审查、archive-light 自动升级”同步到所有消费者，并用 mutation 测试同时覆盖源入口和安装资产。文档只解释同一语义，不新增状态或审批点。

### 7. 业务上下文路由是声明式白名单，不是源仓库业务知识

`business_terms` 挂在目标项目 registry 的每个项目声明下，包含术语、同义词和相对源码路径。`business-terms` 只做确定性路由：按查询词匹配 term/synonym，输出项目、项目卡和路径，不读取或输出正文，不自动扩张白名单。源仓库 registry 保持空数组，测试使用非业务 fixture，避免违反安装器知识分层。

## 替代方案

- 完全取消 OpenSpec：流程最轻，但会失去跨会话状态与可审查契约，不采用。
- 严格模式统一只确认一次：对 Schema、资金和破坏性计划风险过高，不采用；改为风险触发。
- Archive 永远复用 Verify 结果：无法覆盖主规格合并后的新状态，不采用；仍运行专用新鲜门禁。
- 自动删除所有 `.ai-local`：可能删除活跃审查和锁，不采用；只允许按已归档 change 精确清理。
- 只修复 Codex 源入口：无法阻止 Claude 或安装资产回归，不采用；必须覆盖双入口和安装资产。
- 引入自由文本语义搜索或导入 ai-pms 业务词：会扩大敏感信息暴露和源仓库业务知识回流风险，不采用；仅做声明式白名单路由。

## 风险与控制

- 可选 design 可能被滥用：用跨模块、新依赖、状态模型和替代方案作为正向触发条件，并增加 mutation 测试。
- 条件式二次确认可能漏判：硬编码不可跳过的风险集合，未知情况仍等待确认。
- 轻量 Archive 可能遗漏语义变化：以 Verify 后 diff 分类，工作流入口、技能、脚本、测试或治理规格变化即升级全量。
- manifest 清理降低本地诊断能力：先持久化最终身份和结论，清理只发生在已归档状态。
- 文档数量增加可能造成新漂移：mutation 测试检查关键旧口径不得回归，并要求源文件与安装资产的关键语义一致。
- 业务词登记可能过期：查询只声明路由不证明源码事实；文档要求目标项目维护者以项目卡和权威源码复核，缺失项目只报告 missing，不自动获取。

## 当前用户修改保护

实现使用 `feature/align-workflow-semantics-and-business-context` 的隔离 worktree，基线为 `main`。若目标文件出现新的用户修改，立即暂停并重新隔离或请求决定。
