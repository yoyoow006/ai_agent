# 变更：精简 AI 助手工作流并补齐业务上下文路由

模式: 严格
状态: 构建中

## Why

现行工作流已经通过快速、标准、严格三档避免所有任务统一走重流程，但仍有三类机械成本：标准模式固定创建四件套，即使没有独立架构决策；严格模式容易把每个 checklist 都解释为一次任务级审查；Verify 与 Archive 对未发生实质变化的工作流状态重复运行耗时较长的完整契约套件。`.ai-local/reviews` 还会长期保留已归档任务的本地 manifest，增加维护者理解和清理成本。

本变更进一步把流程成本绑定到可观察风险边界：文档数量由设计复杂度决定，审查次数由高风险实现单元决定，完整验证由实际代码/治理语义变化决定。本轮不削弱权限、资金、Schema、迁移、并发一致性和破坏性操作的硬门禁，也不放宽用户修改保护、外部副作用授权或完成前新鲜验证要求。

收口检查发现新版语义已经进入 Codex 根入口、主规格和校验脚本，但 Claude 根入口、用户文档、共享知识总览、部分阶段技能和便携安装资产仍保留旧口径；如果直接交付，源仓库与安装到目标项目的助手会执行不同规则。同时，通用项目 registry 只有项目、应用与源码搜索事实，缺少从业务词到项目卡和源码路径的路由层，目标项目安装后需要手工翻找上下文。

## What Changes

- 标准模式允许在没有独立架构决策时使用三件套：`proposal.md`、delta `spec.md`、可执行 `tasks.md`；只有存在跨模块取舍、新依赖、状态模型或重要替代方案时才增加 `design.md`。
- 严格模式仍先确认规范；第二次计划确认改为风险触发：权限、资金、Schema/迁移、破坏性动作、外部副作用或计划引入未确认选择时必须确认，其余严格任务若计划只是展开已确认方案，可连续进入 Build。
- 严格模式的任务级审查按“高风险实现单元”触发，不按 checklist 数量机械执行；Verify 仍保留规格符合性与质量两个独立关注面。
- 增加归档专用轻量门禁：检查主规格合并、OpenSpec、工作流 core、diff 和 Git 状态；若 Verify 后仅发生机械归档与规格合并，不重复运行顶层契约套件。工作流可执行文件、契约测试或治理语义在 Verify 后变化时仍强制完整门禁。
- Archive 在归档记录持久化最终 manifest ID、comparison base、未验证范围和残余风险后，可以清理该变更的 `.ai-local/reviews/<change>/` 本地缓存；活跃或陈旧待复审 manifest 不得清理。
- 更新根入口、阶段技能、共享审查规则、主规格、校验脚本及 mutation/契约测试，使 Codex profile 下的规则一致且可回归验证。
- 同步 Claude 入口、README、使用介绍、共享知识总览、阶段技能和 `scripts/ai-workflow-assets/` 安装资产，保证双运行时源仓库与安装产物使用同一套三档/条件确认/轻量归档语义。
- 扩展 mutation/契约测试，防止旧“标准固定四件套、严格固定双确认、归档后固定全量”的口径只在一部分入口或安装资产中回归。
- 为声明式项目 registry 增加可选 `business_terms` 业务词路由，并提供只读 `business-terms` 查询：支持项目过滤、精确/包含匹配、同义词、分页和确定性输出；不输出匹配正文、不联网、不 clone、不写目标项目。

## Impact

- 影响 meta库工作流治理：`AGENTS.md`、`CLAUDE.md`、README、使用介绍、`.codex/skills/`、`.claude/skills/`、`.ai/`、`scripts/`、OpenSpec 主规格与测试。
- 影响通用业务上下文层：`.ai/kb/projects/registry.json` 契约、`.ai/tools/project_facts.py`、事实工具测试、项目登记文档及对应安装资产。
- 不修改任何业务子仓库运行时代码、API、数据库 Schema 或部署配置。
- 工作流脚本行为会改变，属于严格模式；实现使用隔离 worktree，保护当前 meta库未提交修改。
- 本地整合建议：验证与独立审查通过后，在用户已确认的策略范围内本地 `--no-ff` 合回 `main` 并复验；不 push、不创建 PR、不删除未合并工作。

## Non-Goals

- 不新增第四种风险模式或新的状态真源。
- 不取消严格任务的规格确认、独立 Verify、OpenSpec required 校验或外部副作用授权。
- 不把 `.ai-local` 变成提交证据；归档后的持久证据仍位于 OpenSpec 归档文件。
- 不自动清理未知目录、活跃 review、未合并分支或包含未提交修改的 worktree。
- 不把 `/media/shitou/data2/ai-pms` 的具体业务事实、项目名、服务名、源码路径或文档搬入本仓库；源仓库 registry 继续保持空白，仅交付目标项目可自行登记的通用业务词路由能力。
