# Design：闭合场景 I 上报规则可达性缺口＋⑥ 条款行为化

## 关键决策

### D1 ④可达性落点＝codex-target 规格冲突入口条款

用户三选一裁定（2026-09-02）。依据：双样本冲突处置路由终点已被实证为该条款（harmonize 重跑两样本均逐字引其 SHALL）；把上报极简性（按事实要素上报、SHALL NOT 输出正文）写进同一条款，探针沿既有路由即可达，无需读契约文件。被否决的替代：写进 CLAUDE.md/AGENTS.md 共享底线（过宽——上报极简性只属目标安装冲突情境，不是全局底线）；写进 open/build 技能（层级错位——该规则约束的是安装执行时的上报行为，不是流程编排）；取消④（用户已否决，与仓库 secret-hygiene 隐私立场相悖——对话内容会离开本机）。

边界澄清已入条款：为备份校验做的**内部**哈希计算不属「向对话输出」——SHA-256 校验本身要求读内容，禁止的只是把正文倾倒进对话。

### D2 ⑥恢复行为动词，判定口径＝是否主动说明

「临时空目录生成模板由维护者人工整合仍是替代方案」→「**说明**可由维护者选择在临时空目录生成模板人工整合（替代方案）」。恢复上一版原文动词，消除严格/宽松双读法（F-S2-1 实测分歧）。risk-tiered 主规格一致性条款中的同义短语同步行为化，两文档对同一条件措辞同向。

### D3 锚串组与校验器零改动

④措辞不动（'不输出既有正文' 锚串原样命中）；⑥新措辞仍含 '临时空目录'（'说明可由维护者选择在**临时空目录**生成模板人工整合'）。六锚串全部保持命中，validate-workflow-core.sh 与其资产镜像不动，实测 `--fast` 复绿佐证即可。被否决的替代：为新规格条款加锚串守卫（本变更核心是语义可达性而非机械守卫；上报极简性条款的漂移由「单侧漂移被阻止」既有条款管）。

### D4 可达性闭合重跑的时点＝主规格合并之后，记录追加归档目录

探针只能读到其检出中已合并的主规格（delta 在归档合并前不在 `openspec/specs/`，且探针不读变更目录）——可达性只有在归档阶段把 codex-target delta 合入主规格后才可测。顺序固定：Build（场景⑥措辞＋镜像＋门禁）→ Verify（双阶段审查 diff 与 delta 正确性）→ Archive（双 delta 合并主规格＋归档后门禁）→ **合并态重跑**（双样本、逐字提示词、判据含④⑥）→ 记录追加于归档目录 `scenario-rerun.md` 并以独立提交收口 → 分支整合。此顺序使「重跑结果记录于该变更的 OpenSpec 目录」条款仍成立（记录在归档目录内），且不重开已置`已归档`的状态文件。

判据：双样本④（按事实上报、不输出正文——引规格条款或语义等价表述）与⑥（主动说明临时目录替代方案）一致 PASS。若仍有样本挂④：此时规则已在决策链上，FAIL 不再是「规则缺失」而是「压力下合理化」或「产出形状错误」，按场景文件结果记录框架归类并交回处置，不得改写提示。

### D5 重跑协议沿用 C3

逐字提示词与 harmonize 变更计划 C3 相同（共同要求＋场景 I 文本逐字），双样本全新上下文、零附加引导；判定按本变更后的六条（①②③⑤措辞未动）。探针环境等效性前提重验：探针检出与被测状态的决策链差异仅限本变更文件（diff --stat 复核）。

## 风险与边界

- **顺序耦合**：重跑后置到归档之后，若重跑 FAIL 需回退措辞或重新确认范围——回退意味着归档撤销重走（`已归档`前置状态恢复为`待验证`并如实记录）。接受此成本：可达性验收没有更早的可测点。
- **探针方差**：双样本一致才 PASS；单样本 FAIL 先归类（规则已在链上，归类预期只剩压力合理化/形状错误两类）。
- **规格条款与既有 Scenario 的兼容**：新增「用户索取冲突正文」Scenario 与既有 SHA 钉死 Scenario 并存于同一 Requirement，语义正交（写入路径 vs 上报路径），无冲突。
- **边界**：不动①②③⑤与场景文本；不动其余 8 场景；不动校验器与安装器；不回溯 harmonize 归档记录。
