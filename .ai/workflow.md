# AI 工作流（精简版 · 单一事实源）

> `.claude/CLAUDE.md` 和 `.codex/AGENTS.md` 只是指向本文件的入口。
> 修改流程规则只改这里，不要改入口副本。

## 风险分级

| 模式 | 适用 | 流程 |
|---|---|---|
| 快速 | 文档、注释、格式化、不影响运行时行为的修改 | 核对事实 → 直接改 → 针对性验证 |
| 标准 | 一般运行时代码变更 | 计划确认 → 实现 → 验证 → 完成 |
| 严格 | 认证/账务/删除迁移/Schema/并发/跨服务契约/破坏性操作 | 计划+设计确认 → worktree 隔离 → TDD 实现 → 双向验证 → 完成 |

不确定风险时，按更高一级处理。开始前向用户说明所选模式。

## 变更管理（取代 openspec 重流程）

- 标准及以上变更，在 `changes/<名称>.md` 建一个文档即可，包含：
  `模式` / `状态` / `目标`（3-5 句）/ `设计要点`（仅严格必填）/ `任务清单`（checkbox）
- 状态只有四个：`待确认 → 进行中 → 待验证 → 完成`；用户明确取消时记 `已取消` + 原因。
- 未获用户明确确认，不得从"待确认"进入实现。
- 归档：完成后把文件移入 `changes/archive/`。不拆 proposal/design/tasks 多文档。

## 实现纪律

- 默认 feature 分支 `feature/<变更名>`；严格模式必须用 worktree 隔离；快速模式不建分支不建变更文档。
- 运行时行为和缺陷修复用 TDD（先失败测试再实现）；纯文档用内容+格式校验。
- 每个职责单元一次可独立回滚的提交。
- 遇到新坑立即写 `.ai/memory/<模块>.md`；完成时把可复用经验沉淀进 memory。

## 验证

- 完成声明前必须实际运行验证（测试/构建/脚本），读取退出码，不凭推断宣布完成。
- 标准模式：完成后一次综合自查（diff + 测试全绿）。
- 严格模式：自查之外，请用户或独立会话复核一次。

## 底线

- 外部副作用（发布、发消息、删除、迁移）必须用户明确授权。
- 范围扩大或风险升级：暂停，更新变更文档，重新确认。
- 不确定时不猜，先查证再动手。
- 审查意见先验证有理再改。

## Skill 加载

- `.claude/skills/` 和 `.codex/skills/` 由 `scripts/sync.sh` 从 `.ai/skills/` 生成，**不要手改**。
- 按各 skill 的 description 触发条件按需加载。
