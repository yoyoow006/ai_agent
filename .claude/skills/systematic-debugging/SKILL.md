# Systematic Debugging

1. 复现：拿到稳定的失败用例/报错，保留完整输出。
2. 缩小：二分定位——注释/日志/git bisect，圈定最小可疑范围。
3. 假设：写下一个明确的根因假设。
4. 验证：做最小实验证实或证伪假设；证伪就回到第 3 步，不许带着未验证假设改代码。
5. 修复：根因处修，不做顺手的表面修补。
6. 回归：确认原用例通过 + 不引入新失败。
7. 新坑写入 `.ai/memory/<模块>.md`。
