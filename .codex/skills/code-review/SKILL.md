# Code Review

每个 finding 必须包含：位置、证据、影响、建议处置。分级：

- **Critical**：错误行为、安全问题、数据丢失风险 → 必须修
- **Important**：边界遗漏、并发问题、明显性能问题 → 应修
- **Minor**：风格、命名、可读性 → 可留

规则：
- 只审 diff 范围及直接相关代码，不扩大。
- 审查意见先自己验证有理再提，不凭感觉。
- 作者对不合理意见可用证据反驳。
- 结论明确说"通过"或"需修改"，不模糊。
